When to use a project

A project is a self-contained workspace — its own chats, its own knowledge, and its own instructions, all in one place. Claude keeps that context every time you come back, so you're not starting from scratch or re-explaining yourself.

Two things make a project powerful:

  • Project knowledge — upload the files and reference docs once (an SOV, guidelines, a template), and Claude uses them across every chat in the project without you re-attaching them.
  • Project instructions — set how Claude should work in this project (tone, format, what to always check), and it follows them in every chat there.

Reach for a project when you have:

  • Recurring work for one account — keep all the chats, SOVs, and docs for a single association together.
  • A multi-step task — like building training docs, where several chats feed one deliverable.
  • Anything with reference material — upload the files or notes once and Claude uses them across every chat.
Why it helpsWithout a project, every new chat is a blank slate. With one, Claude already knows the account, the files, and how you like things done — so you stop repeating yourself.
